# IP 纯净度评审记录

日期：2026-11-25。分支 `feature/ip-purity-check`。按功能日志，本轮不做逐步审查，代码完成后做一次统一检查。

## 结论

可以交给用户在本机点一次「开始检测」和一次检测中关窗。自动测试与实网已经通过。第一轮审查改掉了关窗迟到结果；补测和夹具来源之后，三名新的审查都通过，没有新的阻塞问题。其余为未现场确认项，不阻断当前分支上的使用。

## 已修复

审查指出：关窗确认只调用 `RequestCancellation()`，页面自己的取消才会增加代际号。于是关窗期间仍可能把完成快照画上去，编排器在任务都结束后也可能继续评分并发布。

已改为：

- `MainWindow.OnClosing` 在取消令牌之前调用 `AbandonIpPurity()`。
- `AbandonPendingResults` 增加代际号并停掉慢提示，关窗路径不再把界面改写成空状态。
- `IpPurityRunner` 在汇总评分和发布完成快照之前检查用户取消。
- IPv6 的「已结束」和地址放在同一把锁里。
- UDP 行里，协议不同的地址写成「协议不同，不计入泄漏」，不再写成「与出口一致」。

对应测试：`Run_DoesNotPublishAFinishedScoreAfterTheCallerCancels`，以及 ViewModel 在放弃之后不接收完成快照、慢提示保持空白。

## 审查范围

- 需求：分数只含网络身份和隐私标记；分流出口单独评估；STUN 泄漏含同协议条件；白名单、不跟随重定向、诚实 UA；不拒绝 fake-ip。
- 架构：新任务类型、导航序号 0–6、关窗无 15 秒上限、结果经 Dispatcher 上屏。现有六个页面的行为没有改。
- 测试：v1 与 `score-v1.json` 逐字段一致；取消、超时、白名单、分流情报和 ViewModel 互斥有用例。

第一轮的测试审查被会话中断，没有收口。补上两处之后重新审查：关窗测试会先放弃、再送出 100 分的完成快照，界面仍保持检测中的空分数；`score-v1.json` 可由 `upstream-score.js`（上游 `96166cf`，本地为 CRLF）和 `generate-score-v1.js` 原样再生。三名审查结论都是通过。排除实网后的全量测试仍是 600 通过、0 失败、44 跳过；把实网项算进跳过则是 45 跳过。

## 留下的边界

- 真实关窗对话框和其余六项导航胶囊没有逐项点过。
- 取消截图是状态复原后的渲染，不是按钮点击录像。
- 一个境外 STUN 地址与 HTTP 出口不同就会记为泄漏。这是约定的规则；第二跳代理或单台异常映射也会显示成泄漏。
- `BackgroundOperationKind` 的数值因插入 `IpPurityCheck` 而变化。仓库里没有把这个枚举存进配置。
