## 实现与接入

- 引擎 `Services/Cleanup/`（零第三方依赖）：16 条内置规则（通用 5 + AI 管家 11），AI 五分类处置——可再生缓存默认清（永久）/ 日志按年龄 >7 天 / 会话衍生物 >30 天 / 文件型对话记录 >90 天进回收站（默认不勾）/ 模型与对话数据库仅展示。
- 安全：PathGuard 两遍校验（解析 + 删除前重读属性与全链链接检查）、四锚点白名单、结构性拒绝区、永不名单（CLAUDE.md/AGENTS.md/memories/config.json 本体 + db.sqlite/-wal/-shm 按文件）、云占位拒删、24h 新鲜度；文件匹配/keep-N/只统计类遍历不入册子目录（空目录修剪不越出规则语义边界）。
- 删除：永久走两段句柄式 `DELETE_ON_CLOSE`（探针句柄验属性 → 布防句柄关闭即删，路径解析只发生在打开瞬间，封堵校验后换 junction 的微窗口；占用文件逐条记 Failed 继续）；回收站 `SHFileOperationW`（FOF_ALLOWUNDO，原样路径失败且 ≥260 才 `\\?\` 重试）；模拟模式同审计格式。
- 审计：`%APPDATA%\JLinkRTTViewer\cleaner\audit\cleanup_*.log`（UTF-8、逐条带时间戳、保留 20 份，**每次写入后即校验，写失败当场中止**——不存在无审计删除窗口）；设置 `cleaner\settings.json`（阈值可调、原子写、损坏时清理中止而非静默用默认值）。
- UI：`Pages/CleanupPage` + `ViewModels/CleanupViewModel`；扫描/清理经 `BackgroundTaskHost`（新增 `DiskCleanup` 种类，与烧录/打包互斥，关窗文案已覆盖）；规则行悬停显示「这是什么/删了会发生什么/降级原因」；清理前带 owner 的 MessageBox 二次确认（永久/回收站分列）；清理完成后扫描数字整体失效，需重新扫描。
- 设计决策记录：内置规则首发（不做外置 JSON）、三级删除策略、仅用户级范围（无提权）、对话记录区分文件型与数据库型——依据 2026-11-10 本机实测（.zcode 5.7G：artifacts 828M/177 目录、db.sqlite 1.4G；`*-updater` 3.9G；vm_bundles 10G；codex 追踪 16.6G）。
