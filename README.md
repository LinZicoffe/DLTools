# DL小工具

C# / .NET 8 / WPF 的常用工具集合。左侧选择“固件烧录”“项目打包”“离线授权”或“IP 扫描”，右侧保留对应页面状态。默认进入烧录页；窗口默认1280×800，最小1000×700，表单可滚动。

## AI 开发说明

**本项目大部分代码、界面和文档由 AI 辅助编写与完成。** 开发者负责提出需求、选择方案、集成、测试及验收。欢迎通过 Issue 或 Pull Request 反馈问题、提出建议和参与改进。

## IP 扫描

1. 左侧选择“IP 扫描”，输入本机同网段任一完整 IPv4，例如 `192.168.1.99`。输入非法、IPv6 或带 CIDR 后缀时即时提示并禁用扫描。
2. 点击“开始扫描”，固定扫描 `192.168.1.1`～`192.168.1.254`，跳过 `.0`、`.255`。最多同时探测 32 个地址，每个地址超时 500ms。
3. 列表实时追加可达设备的 IP、往返延时（ms）与状态；进度按已探测地址计数。小于 1ms 的回复可显示 `0`。
4. 随时点击“取消扫描”；程序等待在途 Ping 退出后恢复扫描按钮，保留本轮已发现设备。切页不停止扫描，返回保留输入、进度和结果；重新扫描会清空上一轮结果。

本机需有与目标前三段一致的在线 IPv4 网卡；没有匹配网卡或网卡离线时会显示原因。仅支持固定 /24，不支持自定义掩码、IPv6、主机名或端口扫描。输入末段为 `.0` 或 `.255` 仍按相同范围扫描。现有工具没有 IP 连接目标，不提供双击回填。

未发现设备时显示“未发现设备（部分设备会禁用 ICMP 回复）”。防火墙、ICMP 禁用或超时都可能造成漏检，结果不代表完整资产清单。扫描使用 .NET `Ping`，无需外部 ping 程序。与烧录、打包、授权任务共用全局互斥；扫描中关窗需确认取消，并等待探测退出。

使用截图、实网结果及验证边界见[IP 扫描验收记录](docs/验收记录-IP扫描.md)，阶段提交及审查见[功能日志](IP扫描功能更新日志.md)。需要重跑本机实网测试时，显式指定本地网段：

```powershell
$env:DLTOOLS_IPSCAN_INTEGRATION = '1'
$env:DLTOOLS_IPSCAN_TARGET = '192.168.1.99' # 改成本机在线网卡同网段地址
dotnet test "tests/DLTools.Tests/DLTools.Tests.csproj" -c Release --filter FullyQualifiedName~IpScan
```

默认测试跳过这两项实网测试。证据 JSON 默认写到测试输出目录的 `TestResults`；可用 `DLTOOLS_IPSCAN_EVIDENCE` 指定证据目录。

## 离线授权

此页面是我方内部六位授权码生成器，现场和生成端均无需联网，客户不用收发授权文件。当前版本不对烧录、打包功能施加授权限制。

### 正式交付与日常使用

1. 打开“离线授权”，输入客户／设备名称并新建档案。每个档案具有独立设备标识和随机密钥，请及时备份。
2. 交付前由我方可靠预置对应设备标识和密钥到客户软件或设备。新建档案不会自动完成客户配对；当前提供 DEMO，真实客户项目的密钥预置仍需接入。
3. 日常授权时选择正确档案，输入现场提供的六位申请码，例如 `000012`，点击“生成授权码”。前导零会保留。
4. 点击“复制授权码”，将六位结果告知客户。客户输入后由验证端确认并保存激活状态。更换档案或申请码后旧结果立即清空；切换工具页面保留输入和结果。

“客户／设备名称”和“当前档案改名”只用于显示。**改名不会改变设备标识或密钥，不能用改名完成配对。** 客户应告知申请码及所属设备，生成端必须选择对应档案。

### 备份、密码与换电脑

用“创建加密备份”保存我方 `.dlauth` 档案备份，设置至少 16 字符的独立强密码；用“从备份恢复”导入并确认合并。现有其他档案保留，同设备不同密钥拒绝覆盖，恢复确认期间库有其他修改时要求重新预览；损坏库恢复前保留原文件副本。

| 场景 | 密码与恢复方式 |
|---|---|
| 本机正常启动、重新加载已保存档案 | 无需输入备份密码，由当前 Windows 用户 DPAPI 解密 |
| 从 `.dlauth` 恢复 | 需要创建该份备份时设置的密码；软件不会自动单独保存密码，也没有找回入口 |
| 忘记旧备份密码，但本机档案仍可用 | 重新创建一份备份并设置新密码，不需要旧密码 |
| 本机档案已丢失，只剩加密备份且忘记密码 | 必须找回原密码；软件不能绕过或重置该备份密码 |

备份使用 AES-256-GCM 和 PBKDF2-HMAC-SHA256。备份与密码由我方分开保管，客户无需接收或提供这些文件。跨电脑恢复使用加密备份，直接复制当前用户加密的 `profiles.dat` 不保证可解密。

### WinForms / WPF DEMO 快速测试

源码、启动脚本和完整构建说明位于 [DEMO](DEMO/README.md)，使用独立解决方案。

1. 运行 `DEMO/启动WinForms.cmd` 或 `DEMO/启动WPF.cmd`。本机已发布运行文件；从 Git 获取源码后需按 DEMO 说明先构建、发布。
2. 在 DL小工具下方“我方档案备份”区域点击 **“从备份恢复”**，选择 `DEMO/DEMO公开测试档案.dlauth`。该文件未提交到 Git，若不存在，可点击任一 DEMO 的“导出生成器测试档案”生成。
3. 输入测试备份密码 `DLTools-Demo-Only-2026!`，确认恢复；在上方下拉框选择 **“DEMO公开测试设备（禁止生产使用）”**。
4. 核对设备标识为 `11112222333344445555666677778888`，将 DEMO 的六位申请码填入生成器，再把生成的六位授权码填回 DEMO。
5. 激活后测试受控功能，关闭重开验证保存；“重置测试授权”可重新演示。WinForms 与 WPF 的状态独立。

**必须恢复对应测试档案；新建随机档案或只把原档案改成 DEMO 名称，不能完成配对。** 首次导入仅用于我方测试配对，之后只交换六位申请码和授权码。

两套 DEMO 会保存当前申请，累计输错五次后暂停 30 分钟，重启或更换申请不清除失败次数；冷却结束后点击“刷新状态”。状态保存失败不报告成功，时间倒退时暂停授权。公开测试密钥、导出和重置入口仅供演示，不能直接用于真实客户交付。

### 接入边界

`OfflineAuthorizationService.Verify` 只完成计算比较；真实客户软件仍需预置独立密钥，接入申请生命周期、错误限次和授权状态保存。六位码不承载有效期或功能套餐，也不能替代首次密钥配对。

纯 Windows 实现不承诺抵抗逆向、密钥提取、删除或回滚状态。重装电脑可能丢失密钥与激活状态；能重新预置同一密钥时可再次申请，否则需要重新配对，不能保证重装后自动保留授权。

计算协议与公开向量见[设计文档](docs/设计-六位离线授权.md)，生成端验证见[离线授权验收记录](docs/验收记录-六位离线授权.md)，DEMO 开发及用户验收见[DEMO 功能日志](离线授权DEMO功能更新日志.md)。

## 固件烧录

- 支持`.elf` / `.axf`（ELF32 LOAD段）、`.hex`（Intel HEX）和`.bin`（需填写起始地址）。
- 配置目标设备、SWD/JTAG、速度和J-Link序列号；支持整片/扇区擦除及完成后的复位动作。
- 烧录后强制按4096字节分块读回比对；校验通过表示写入内容通过当前校验流程，不代表固件业务已正常运行。
- 开始烧录时才加载J-Link；缺少驱动不影响打开程序和项目打包。
- 日志区支持手动拖动、横向滚动和新日志自动滚动到底部；烧录日志布局修复已合并到主分支。

目标芯片需要手动填写 **J-Link 设备库中的名称**，当前不会自动识别完整型号，也不会自动校正与实板不符的选择。例如实板 `STM32H723ZGT6` 对应设备名 `STM32H723ZG`；填写完整丝印可能提示不支持。“目标已连接”显示的是选定名称，不代表已确认实板型号。支持范围取决于实际加载的 J-Link 驱动和探针，当前软件未逐款验收。

“序列号”填写 J-Link 探针的 USB 序列号，留空自动选择；例如 `COM10` 是串口名称，不能代替该序列号。

流程：Connect → 可选整片擦除 → 按段halt/BeginDownload/WriteMem/EndDownload → 强制Verify → 可选Reset → Close。取消保留原来的段/校验块边界；关窗确认停止后最多等待15秒。

## 项目打包

1. 导入本地文件夹、`.sln`或C# `.csproj`，点击“识别”。多个入口/目标框架时手动选择候选。
2. 查看WPF/WinForms、.NET版本、构建配置、项目平台、CPU、入口EXE和识别依据。直接项目修改配置/平台后需重新评估；解决方案采用候选对应的ActiveCfg映射。
3. 指定输出目录、安装包文件名、部署架构及模式。默认独立部署，可改为依赖目标机Desktop Runtime；Framework沿用项目CPU并显示运行时要求。
4. 开始打包，查看实际阶段和实时日志；支持取消，成功后可打开输出目录或完整日志。

安装包文件名、安装后的应用名称和目标EXE独立处理。更改包名不会重命名程序入口，也不会改变项目的稳定AppId。

### 支持范围与工具

| 项目/操作 | 要求 |
|---|---|
| 工具自身运行 | Windows 10/11 x64，.NET 8 Desktop Runtime |
| 工具自身开发 | .NET 8或兼容更新SDK |
| 现代.NET WPF/WinForms | 对应SDK，MSBuild17.8+；发布win-x86/win-x64，遵守项目CPU/RID约束 |
| 传统/SDK格式Framework WPF/WinForms | Visual Studio MSBuild17.8+及对应Developer Pack；支持x86/x64/AnyCPU |

可在“构建工具与路径设置”中自动定位、手动指定及检查dotnet、MSBuild和ISCC。ARM64、其他技术栈、ZIP导入和MSI不在首版范围内。

### 自动生成模板

读取项目名称、版本及图标，允许修改，缺少版本默认1.0.0。默认包名为`<应用名>_v<版本>_Setup.exe`。支持额外文件/目录映射到安装目录下的相对位置；目录目标`.`表示合并安装根，文件目标须包含文件名。越界、链接和重名冲突会拒绝。

默认当前用户安装，提供开始菜单、可选桌面快捷方式、卸载和安装后启动。稳定AppId按完整项目路径保存；升级时保持该值。模板不添加递归删除用户数据的卸载规则。

### 使用已有脚本

选择原`.iss`及其实际读取的构建输入目录；现代项目通常为脚本旁`Publish`，Framework可用正常TargetDir。工具先构建，再准备输入并编译原脚本；原脚本的AppId、授权、图标、安装及卸载规则继续生效。通用应用信息和额外资源控件在此模式下禁用。

输入路径必须与脚本Source/宏匹配，工具不推断自定义宏。脚本须支持ISPP有效规则检查；builtin预处理器和无法导出规则的脚本会明确拒绝。首版只输出独立单EXE安装包，拒绝分卷、external、下载及安装包旁附属文件依赖。编译器参数控制输出目录和包名；不会改写原脚本。工具不主动读取授权文件内容写入日志；私密预处理文本会删除且不入日志。

### 任务与文件恢复

全局一次执行一个烧录、项目、授权档案或 IP 扫描任务，切页不会释放运行资格；打包关窗会等进程退出和目录恢复，授权档案任务会等安全保存结束，IP 扫描会等在途探测退出，均不使用烧录的15秒上限。退出问题与打包覆盖问题按顺序显示。

现代.NET发布到本次任务的独占目录；Framework先确认备份入口正常输出目录，再还原/重新构建并整目录收集。保留运行时、原生库、语言资源、XML/JSON，只过滤调试产物。已有脚本的非空输入目录同样需要确认备份。成功后保留旧目录备份；失败或取消恢复旧输入和旧安装包，部分输出另存保留。

安装包先在目标卷暂存并校验，再原子提交；覆盖同名包需要确认。恢复异常会显示备份及记录位置，阻止相关父子目录重试。应先按记录恢复文件，再处理相应恢复记录，避免绕过保护。保留的任务产物和备份需按需人工归档。

## 构建与测试

### 下载源码并编译

下载或克隆**完整仓库**，保留目录结构。根目录的 [DL小工具.sln](DL小工具.sln) 已纳入版本控制，发布源码时应与 `烧录上位机程序/`、`tests/` 等目录一同上传；只下载 `.sln` 无法编译。

在 Windows x64 上安装 .NET 8 SDK（或支持此目标框架的更新 SDK）。可用 Visual Studio 2022 17.8+（安装“.NET 桌面开发”工作负载）直接打开 `DL小工具.sln`，选择 Release 构建并将 `DL小工具` 设为启动项目；也可使用下面的命令行操作。NuGet 依赖在还原时下载，无需预先放入仓库。编译主程序不需要 J-Link 驱动或 Inno Setup；实际烧录和生成安装包时再安装对应工具。

### 命令行构建与测试

在仓库根目录使用PowerShell：

```powershell
dotnet restore "DL小工具.sln"
dotnet build "DL小工具.sln" -c Release
dotnet run --project "烧录上位机程序/DL小工具.csproj"
dotnet test "tests/DLTools.Tests/DLTools.Tests.csproj" -c Release
```

DEMO 另行构建与测试，主解决方案不会自动包含它：

```powershell
dotnet build "DEMO/离线授权DEMO.sln" -c Release
dotnet test "DEMO/离线授权DEMO.sln" -c Release
```

发布运行文件及启动脚本的准备方式见 [DEMO 构建说明](DEMO/README.md)。复制到测试机时复制整个对应发布目录，不能只复制 EXE。

普通测试不执行实际安装，项目识别用例也会调用实际SDK、VS MSBuild17.8+并检查Framework4.8开发包。完整发布/安装集成检查需本机SDK8/9、Framework4.8开发包、VS MSBuild和Inno：

```powershell
$env:DLTOOLS_INTEGRATION = '1'
$env:DLTOOLS_INSTALL_INTEGRATION = '1' # 允许测试独立安装、升级和卸载临时验证应用
dotnet test "tests/DLTools.Tests/DLTools.Tests.csproj" -c Release
```

安装测试只使用独占临时目录和新AppId，不使用真实业务应用标识。安装、GUI及硬件边界见[验收记录](docs/验收记录-DL小工具.md)。

保留原命名空间和`%APPDATA%/JLinkRTTViewer/`根目录。烧录设置仍为`user_prefs.json`，原日志位于`logs/`；打包配置为`packaging/profiles.json`，任务日志/产物在`packaging/runs/<任务ID>/`，恢复记录在`packaging/recovery/`。目录备份位于相同卷的`.dltools-backups/`，具体位置由结果和日志列出。

授权档案独立保存在`authorization/profiles.dat`；该文件整体由当前用户DPAPI加密。不要手工编辑或删除密钥库，不要将其或加密备份提交到仓库。

DEMO 状态分别保存在 `%LOCALAPPDATA%/DLTools/OfflineAuthorizationDemo/WinForms/state.dat` 与 `WPF/state.dat`，与生成端档案隔离。“重置测试授权”只重置对应 DEMO，并保留旧状态副本；不会删除生成器中的真实档案。

J-Link DLL可放在EXE旁，也支持SEGGER安装目录、IAR捆绑目录和PATH定位。
